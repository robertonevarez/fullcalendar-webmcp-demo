# Multi-Resource Scheduling

Real-world appointments often require more than just a single human provider. A viable appointment frequently requires the simultaneous availability of multiple distinct resources.

---

## The Resource Matrix

Consider these archetypes:

* **Physical Therapy Clinic**: Requires **1 Physical Therapist** + **1 Treatment Room**.
* **Auto Service Center**: Requires **1 Diagnostic Mechanic** + **1 Dedicated Service Bay**.
* **Day Spa / Salon**: Requires **1 Massage Therapist** + **1 Private Massage Room**.

```text
Time Window: 10:00 AM – 11:00 AM

Therapist A:  [ AVAILABLE ]
Therapist B:  [ BOOKED    ]

Room 1:       [ BOOKED    ]
Room 2:       [ AVAILABLE ]

Combined Slot: [ AVAILABLE: Therapist A + Room 2 ]
```

---

## Declaring Resource Requirements

In Protocol Tooling, a `Service` defines its multi-resource requirements as an array:

```json
{
  "id": "svc_pt_eval",
  "name": "Physical Therapy Evaluation",
  "resource_requirements": [
    {
      "resource_type": "therapist",
      "quantity": 1,
      "capability": "physical_therapy_eval"
    },
    {
      "resource_type": "treatment_room",
      "quantity": 1
    }
  ]
}
```

The scheduler tests all permutations of available resources and only emits a `slot_id` when the complete set of required resources is simultaneously uncommitted.
