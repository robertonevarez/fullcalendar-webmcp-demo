## 1. Package — P0.1 WebMCP execute contract

### Problem

Five of six tools required destructuring `{ signal }` from the second execute argument:

```ts
async execute(input, { signal }) { ... }
```

When a caller invoked `execute(input)` with one argument (agent shim / older path), tools threw:

`TypeError: Cannot destructure property 'signal' of 'undefined'`

`FakeModelContext` always passed `{ signal }`, so unit tests never caught it.

### Authoritative contract

From the WebMCP draft / Chromium imperative path:

- Signature: `execute(inputObject, options)` where `options.signal: AbortSignal`
- Browser **always** invents an `AbortController` and passes `{ signal }`
- `document.modelContext.executeTool(tool, inputObject, { signal? })` is the public invoke API

Second argument is **standard**, not synthetic. Fix keeps AbortSignal forwarding when present; does not require-destructure when absent.

### Fix

| Area | Change |
|---|---|
| `src/tool-definitions.ts` | `executionSignal(options)` via `options?.signal`; all six tools updated |
| `tests/fake-model-context.ts` | Added `executeTool` mirroring browser (JSON round-trip + always `{ signal }`) |
| Tests | One-arg shim regression, per-tool boundary, full sequence, human→agent, write failure, signal forward |
| Version | `0.1.0` → **`0.1.1`** |
| Pack script | Derives tarball name from `package.json` version |

### Public API

**Unchanged.** Same exports, hooks, repository types, tool names.
