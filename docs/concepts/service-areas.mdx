# Service Areas

Field service businesses (such as HVAC technicians, plumbers, mobile auto mechanics, and home care providers) require technicians to travel to the customer's physical location.

To prevent booking jobs that technicians cannot physically service, Protocol Tooling introduces **Zone-Based Service Areas**.

---

## Service-Area Zone Modeling

Businesses define geographic coverage zones (`ServiceAreaZone`):

```json
{
  "id": "zone_acme_central",
  "business_id": "biz_acme_hvac",
  "zone_id": "austin-central",
  "postal_codes": ["78701", "78702", "78704", "78705"]
}
```

---

## Service Flag: `service_area_required`

When a service declares `"service_area_required": true`:

1. **Explicit Check Tool**: The agent can invoke `check_service_area(postal_code)` to verify customer eligibility early in conversation.
2. **Availability Query Guard**: `get_availability` requires `postal_code` and automatically rejects requests for postal codes outside defined zones with `OUTSIDE_SERVICE_AREA`.
3. **Appointment Creation Guard**: `create_appointment` verifies the customer's `service_address.postal_code` before acquiring resource locks.

---

## Evaluation Statuses

The `check_service_area` tool returns three distinct statuses:

* **`eligible`**: Postal code belongs to one of the business's active zones.
* **`ineligible`**: Postal code is outside all active zones.
* **`not_required`**: The requested service does not mandate geographic bounds (e.g. an in-salon appointment or remote consultation).
